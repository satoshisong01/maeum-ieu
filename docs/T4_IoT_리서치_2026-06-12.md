# T4 — IoT 디바이스 패키징 리서치 v0.1

> 2026-06-12 초안. 스마트폰/태블릿이 익숙하지 않은 어르신에게 "전원만 꽂으면 되는" 전용 기기로
> 마음이음(T2 대화·수동 선별 + T3 자가점검)을 배달하는 트랙. T1~T3 기능 위에 얹는 하드웨어 레이어.

## 0. 제품 요구 (어르신 관점에서 역산)

- **설정 0회**: 박스 개봉 → 전원 연결 → 끝. WiFi 비밀번호 입력도 없어야 함 → **셀룰러 내장이 기본값**
- 조작: 버튼 0~1개 (말 걸면 응답하는 상시 대기 or 큰 버튼 1개). 화면은 선택사양
- 원거리 음성: 2~3m 거리, TV 소음 환경에서 인식 (far-field 마이크 + 에코캔슬)
- 응급 동작: "사람 살려" 류 발화 → 기존 L3 응급 파이프라인 → 보호자 통보 (기기 LED/사운드 피드백)
- 월 유지비(통신비 포함)가 구독료 안에 흡수 가능한 수준

## 1. 아키텍처 후보 3안

### A안 — ESP32-S3 오디오 프론트엔드 (초저가 양산형) ✅ 권장 출발점
- 구성: ESP32-S3 + I2S 마이크(INMP441/2-mic) + 앰프(MAX98357A) + 스피커 + LTE 모뎀
- 역할 분담: 기기는 **웨이크워드 + 오디오 캡처 + WebSocket 스트리밍만** (Espressif AFE로 노이즈/웨이크워드 처리). STT·LLM·TTS·안전망은 전부 서버 — **현재 서버 자산을 그대로 재사용**
- 검증된 패턴: Home Assistant Voice(ESP32-S3-BOX), 오픈소스 ESP32 보이스 어시스턴트 다수가 16kHz I2S → WS 바이너리 스트리밍으로 구현, 전송 지연 <100ms. 프록시에서 Opus 압축 시 70~80kbps
- BOM 추정(양산): 모듈 $5~8 + 마이크 $2 + 앰프/스피커 $5 + LTE Cat.1 모듈 $20~30 + 케이스/전원 $10 ≈ **$45~60/대**
- 한계: 로컬 처리 불가(전부 온라인), 펌웨어 OTA 체계 필요

### B안 — 라즈베리파이(Zero 2 W/CM4) 리눅스 클라이언트
- Node/Python 풀 클라이언트 — 현재 웹 클라이언트 로직(VAD·청크 TTS 재생)을 거의 포팅 가능, Live API 직결도 가능
- ReSpeaker 2-Mic HAT(~$15) 등 far-field 마이크 생태계 성숙. LTE는 USB 동글 또는 HAT
- BOM ≈ $70~110/대. 개발 난도 낮고 반복 빠름 → **파일럿/시제품은 B안, 양산은 A안** 이원화가 현실적
- 한계: 단가·부팅시간·SD카드 내구성

### C안 — 기성품 활용 (개발 0)
- 보급형 태블릿 + 거치대 + 자동 키오스크 모드 (현 웹앱 그대로) ≈ 10~15만원/대
- 또는 통신사 돌봄 스피커(SKT NUGU 돌봄 등) 제휴 — 플랫폼 폐쇄적이라 우리 파이프라인 이식 불가, 제휴 협상 필요
- 파일럿(어르신 5~10명 실사용 데이터)을 가장 빨리 시작하는 길 — **하드웨어 개발과 무관하게 지금 가능**

## 2. 통신 (국내)

| 옵션 | 대역폭 | 음성 스트리밍 | 비고 |
|---|---|---|---|
| LTE **Cat.1** | 하행 10M/상행 5Mbps | 여유 충분 (Opus 양방향 ~50kbps) | **권장.** 모듈 $20~30, 국내 IoT 요금제(KT LPWA·LG U+ IoT Partners) 월 수천 원대 |
| LTE Cat.M1 | 상행 ~1Mbps | 압축 시 가능하나 마진 박함 | 모듈 저렴·저전력. 음성엔 차선 |
| NB-IoT | kbps급 | 불가 | 센서용 — 제외 |
| WiFi 전용 | — | 가능 | 설정 0회 원칙 위배 → 보조 수단으로만 |

- 데이터량 추산: 하루 30분 대화 × Opus 양방향 ≈ 월 0.7~1GB → IoT 요금제 범위 내
- 요금제 실사: KT LPWA / LG U+ IoT Partners 포털에서 Cat.1 단가 견적 필요 (대당 월 2~5천원 예상)

## 3. Live API와의 결합 (docs/LIVE_API_검토_2026-06-12.md 연결)

- 기기→서버 WS 스트리밍(A안)과 Live API의 WS는 같은 결 — 서버 프록시가 기기 오디오를 Live API로 중계하면 **STT 구간 제거 + 기기 펌웨어는 단순 유지**
- 즉 T4의 음성 경로 = Live API TEXT 모달리티 + 서버 후처리 + Cloud TTS 청크 회송 (3장 PoC가 T4의 선행 작업이 됨)

## 5. 리스크 / 미결정

- **원거리 인식 품질**: 현재 시스템은 근접 마이크 기준 — TV 소음·2m 거리에서 STT 정확도 실측 필요 (P0의 핵심 수집 항목)
- **응급 기능의 책임 범위**: 기기가 "응급 호출 기기"로 인식되면 의료기기/안전 규제 검토 필요 — "대화 동반자"로 포지셔닝 유지 권장
- 웨이크워드 vs 상시 듣기: 상시 듣기는 프라이버시·통신비 부담 → 한국어 커스텀 웨이크워드("지윤아") 학습 비용 확인
- KC 인증·전파 인증(양산 시), OTA 업데이트 체계, SIM 조달(eSIM vs 물리)
- 기존 효돌·통신사 돌봄 스피커와의 차별점 = **수동 인지 선별 + T1 전문가 연계** — 하드웨어가 아니라 파이프라인이 해자
