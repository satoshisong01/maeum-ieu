# T3 일반인 정신건강 검진 — 설계 (v0.1, 2026-06-11)

> 목적: 치매와 무관한 일반 성인이 AI와 대화하며 우울·불안 등 정신건강을 자가 검진하고, **결과를 본인이 직접 확인**한다.
> 원칙: ① 표준 척도 기반(자체 발명 금지) ② 진단이 아닌 선별 — 결과 화면에 전문기관 안내 필수 ③ 위험 신호 즉시 개입(1393 등)

## 1. 채점 모델 — 치매 선별과의 차이

| | T1/T2 치매 선별 (기존) | T3 정신건강 (신규) |
|---|---|---|
| 채점 방식 | LLM 분석기가 발화에서 이상 **관찰** (0/1/2) | 사용자의 **응답 자체가 점수** (자기보고식) |
| 문항 성격 | 정답 있는 검사 (요일, 단어 회상) | 정답 없는 빈도 질문 ("지난 2주간 얼마나 자주…") |
| 엔진 | cognitive-analyzer (관찰 채점) | **빈도 응답 → 0~3점 매핑 후 합산** (LLM은 응답을 점수로 분류만) |
| 결과 열람 | 의사·보호자 | **본인** |

핵심: T3는 분석기 재사용이 아니라 **응답 분류기**(사용자의 자연어 답 → 0~3 빈도 점수)가 필요. 분류는 경량(2.5-flash, responseSchema)으로 충분.

## 2. 척도와 대화형 변형 (PHQ-9 예시)

PHQ-9 (공개 척도, 한국어 표준화판 존재) — "지난 2주 동안 다음 문제로 얼마나 자주 곤란을 겪었습니까?"
응답 매핑: 전혀 없음 0 / 며칠 동안 1 / 절반 이상 2 / 거의 매일 3. 합계 0~27.

대화형 변형 원칙: **의미 보존 + 자연어 응답 허용**. 문항 의미를 바꾸면 척도 타당도가 깨지므로 "물어보는 내용"은 유지하고 말투만 부드럽게.

| # | 원문항 (요지) | 대화형 변형 예 |
|---|---|---|
| 1 | 흥미·즐거움 저하 | "요즘 2주 정도, 평소 좋아하던 일이 재미없게 느껴진 날이 많으셨어요?" |
| 2 | 우울·절망감 | "기분이 가라앉거나 희망이 없다고 느낀 날은 어느 정도였어요?" |
| 3 | 수면 문제 | "잠들기 어렵거나 자꾸 깨거나, 반대로 너무 많이 잔 날이 많았나요?" |
| 4 | 피로·기력 저하 | "기운이 없고 쉽게 지치는 느낌은 얼마나 자주 있었어요?" |
| 5 | 식욕 변화 | "입맛이 없거나 과식하게 되는 일은요?" |
| 6 | 자책감 | "스스로가 실패자같다거나 가족을 실망시켰다는 생각이 든 적은요?" |
| 7 | 집중 곤란 | "신문이나 TV에 집중하기 어려운 날이 많았나요?" |
| 8 | 정신운동 변화 | "말이나 행동이 평소보다 눈에 띄게 느려졌거나, 반대로 안절부절못한 적은요?" |
| 9 | **자해 사고** | "차라리 없어지는 게 낫겠다거나 스스로를 해치고 싶다는 생각이 든 적이 있으셨어요?" |

응답 분류기 프롬프트: 사용자의 자연어 답("거의 매일 그래", "글쎄 며칠 그랬나")을 {0,1,2,3,불명확} 중 하나로 분류. 불명확이면 부드럽게 재질문(1회 한정).

**9번 문항 특별 처리**: 점수 ≥1 즉시 — 합계와 무관하게 — 위기 안내 플로우(자살예방 109 / 정신건강 위기 1393, 기존 self_harm 모더레이션 응답 재사용) + 결과 화면 상단 고정 안내.

해석(표준 컷오프): 0-4 정상 / 5-9 가벼운 우울 / 10-14 중간 / 15-19 중간-심한 / 20-27 심한. 10점 이상 → "전문가 상담을 권합니다" + 기관 링크.

## 3. 아키텍처 (재사용 vs 신규)

```
[재사용] 대화 파이프라인(route.ts)·SSE 스트리밍·계정 체계·자살위험 즉시 감지(emergency self_harm)
[신규]
  lib/screening/mental-bank.ts      — 척도 정의(PHQ-9, GAD-7, PSS) + 문항별 대화형 변형 2~3개
  lib/health/mental-scorer.ts       — 응답→빈도점수 분류(2.5-flash, responseSchema) + 합산 + 해석
  mental_assessments (raw 테이블)    — user_id, scale, item_no, score, raw_answer_hash, session_id, created_at
                                      ⚠️ 수동 SQL 생성(db push 금지) + restore-raw-tables.ts에 DDL 추가
  모드: screeningMode에 "mental" 추가? → ❌ 계정 역할과 검진 세션은 별개.
        대신 대화 시작 시 "마음 검진 시작" 진입점(버튼/발화) → 세션 플래그로 검진 모드 9문항 진행 → 종료 후 일상 복귀
  app/mental/page.tsx               — 본인용 결과: 점수·해석·추이 그래프·전문기관 안내 (대시보드 골격 재사용)
```

## 4. 진행 흐름 (사용자 경험)

1. 진입: 채팅 화면 "🧠 마음 건강 체크" 버튼 (또는 "마음 검진 해줘" 발화 감지)
2. 안내+동의: "9개 질문, 약 5분. 결과는 본인만 봅니다" — 1탭 동의
3. 문항 1~9 대화형 진행 (한 턴 1문항, 공감 응답 1문장 + 다음 문항; 분류 불명확 시 1회 재질문)
4. 9번 위험 응답 시: 즉시 위기 안내 + 검진은 계속할지 선택
5. 결과: 점수/해석/지난 검진 대비 추이 + "이 결과는 의학적 진단이 아닙니다" + 기관 안내
6. 재검 주기: 2주 후 재검 권유 (PHQ-9 측정 주기와 일치)

## 5. 구현 순서 (다음 반복)

1. mental-bank.ts — PHQ-9 9문항 × 변형 2개 (GAD-7은 2차)
2. mental_assessments 테이블 + ops 스크립트 + 복구 DDL
3. mental-scorer.ts + 검진 세션 상태 머신(route 분기)
4. 결과 페이지 + 채팅 진입 버튼
5. 검증: 시나리오 12종(명확 응답 4단계 × 2 + 모호 응답 재질문 + 9번 위험 + 중도 이탈 + 재검)

## 6. 리스크 (착수 전 확인)

- **표현 수위**: "우울증 검사"가 아니라 "마음 건강 체크" — 의료기기(SaMD) 표방 회피, 결과 화면 비진단 고지 필수
- **위기 대응 책임**: 9번 양성 시 안내만으로 충분한가 — 보호자 알림 여부는 T3에선 **본인 동의 없이 금지** (T1/T2와 반대 기본값)
- raw_answer 저장 금지(해시만) — 민감 응답 원문 비보존 원칙
